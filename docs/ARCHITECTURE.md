# Architecture and data contract

`generate.py` creates a fixed-seed (420), versioned synthetic source, spanning 1 January 2024 to 14 November 2026. The app reference date is 31 October 2026. Simulator-only parameters live in `evaluation/raw/generator_parameters.json`; they never enter forecasting inputs.

`data.py` validates identifiers, currencies, integer ledger reconciliation, availability timestamps, contiguous zero-cash days and schedule versions. `Sources.snapshot` returns a detached `OriginView`: account metadata, at most 56 historical daily rows, visible transactions and the latest item version known by end-of-day D. Future truth is accessible only through separate training/evaluation functions. Snapshot fingerprints exclude future changes.

An outstanding overdue item is assumed on D+1 and labelled overdue. Cancellation or settlement removes it only after that version becomes visible. Expected date and amount remain distinct from eventual settlement date and amount. Training labels match booked transactions to the origin's known schedule references: up to the known amount is scheduled regardless of timing; excess amounts and unknown items become nonnegative remaining cash. Under-settlement and timing differences remain schedule errors, not negative clipped residuals. Each item settles at most once. This definition avoids predicting gross cash on top of scheduled cash.

`forecast.py` uses four previous corresponding weekdays' remaining flows for the seasonal baseline, with available-history means as fallback. The pooled candidate has 24 calendar, sector, known-schedule and past-flow features; no account ID, country, future settlement or latent simulator parameter is a feature. Amount inputs and targets are scaled by each origin's trailing gross-cash mean (minimum 100 minor units). Scaling uses only that origin's past. Histogram boosting uses Poisson loss for nonnegative estimates, 120 iterations, 15 leaves, learning rate .08, L2=2, seed 420 and no random internal early-stopping split. Predictions round to integer minor units before balances are accumulated.

`evaluation.py` selects on validation, refits the same frozen parameters with newly observable training labels, and scores untouched known and held-out-business tests. Prepared app forecasts are generated offline: five October origins per account, 500 records. UI imports no fitting code. Artifact SHA-256 verification guards accidental bundle changes; forecast IDs cover immutable snapshot/model/path content. Later actuals are separate comparison fields.

`domain.py` owns strict seven-day alerts and deterministic scenario arithmetic. Invalid essential inputs produce Forecast unavailable. Exactly zero is below a positive buffer, not a negative balance. Only future days determine the alert.

`repository.py` provides the same transaction interface for explicit local SQLite and hosted PostgreSQL. `cp_forecasts` is an immutable registry; `cp_workspaces` stores SHA-256 capability hashes; `cp_events` appends Review and Scenario events. Foreign keys, unique workspace/intent keys, server-side account/forecast scope checks and a locked schema gate protect saves. Scenarios are recomputed from registered forecasts. A workspace generation fences writes after reset. PostgreSQL uses short-lived TLS-verified connections with certifi roots, no keepalive polling. Credentials and capability keys are never stored in public artifacts.

`ui.py` supplies one overview and one account-detail view, native keyboard-accessible controls, Plotly charts and horizontally scrollable data grids. Three tabs keep forecast, source movements and human actions distinct. A workspace database failure is reported; no hosted local-file fallback exists.

Schema: `migrations/001_initial.sql` documents PostgreSQL v1 DDL. Use `cashpilot migrate` as the supported initializer: it creates the schema gate and registers prepared forecasts idempotently, rejecting altered content under an existing ID. Future schema changes require explicit versioned migrations and isolated-branch tests; do not treat `create_all` as a general schema-upgrade engine.
